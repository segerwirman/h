# JARVIS Project Rules

## Project continuity
- Before changing code, read in order: `session.md`, the master roadmap named there, `JARVIS.MD`, `.hermes/handoffs/current.md`, this file, then the relevant domain roadmap.
- Treat `session.md` plus the master roadmap as the current phase/order source of truth; after every completed phase, synchronize all continuity files and the relevant domain roadmap.
- Communicate with Takeda in Indonesian.

## Engineering process
- Follow strict TDD: write a focused RED test, run it and observe the expected failure, implement the minimal GREEN change, then run focused regression.
- Run tests without inherited path overrides:
  `unset PYTHONPATH; python -m pytest -q ...`
- Before reporting a phase complete, run:
  ```bash
  python -m py_compile <changed-python-files>
  git diff --check
  python scripts/verify_frozen.py
  ```
- Do not claim test results or runtime behavior without real command output.

## Frozen boundary
- Do not modify files listed in `config/frozen_manifest.json` without explicit user approval.
- Prefer small editable seams, default-off config, dependency injection, and focused regressions.

## Security / authority boundaries
- Default to fail-closed remote authority.
- Do not expose secrets, tokens, credentials, OAuth codes, raw payloads, filesystem paths, raw HTML, cookies, headers, OCR, screenshots, coordinates, UIA references, or browser-login state to Telegram/remote outputs.
- Remote mutation must use an explicit local desktop approval contract.
- Public monitoring stays monitor-only: validated public HTTPS sources; no generic cron task, dispatch.run_sync, shell, browser automation, login, CAPTCHA bypass, typing, UIA, or desktop action.
